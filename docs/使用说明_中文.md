## 三、评分公式（提案 4.2.1 的实现）

对队列中每笔付款 *i*：

```
分数 = w_P·P + w_D·D + w_A·A − w_L·L
```

| 项 | 定义 | 取值范围 | 含义 |
|---|---|---|---|
| `P` | `priority_points[优先级] / 最大分值` | (0,1] | URGENT 1.000、HIGH 0.667、NORMAL 0.333 |
| `D` | `1 − min(1, 松弛秒数 / deadline_normalizer_sec)` | [0,1] | 剩余时间越少，分数越高 |
| `A` | `min(1, 等待秒数 / aging_normalizer_sec)` | [0,1] | 等得越久，分数越高 |
| `L` | `金额 / funding_demand_reference_rmb` | [0,1] | **罚项**：金额越大分数越低 |

其中 `松弛秒数 = 截止时刻 − 当前时刻 − 预期确认延迟 − 安全余量`。

权重默认 `w_P=0.45, w_D=0.40, w_A=0.15, w_L=0.00`，全部读自
`config.json` 的 `ranking_parameters`，代码里没有任何硬编码。

排序规则：**分数从高到低 → 到达时间从早到晚 → payment_id 从小到大**（提案 4.2.2）。
分数先四舍五入到 9 位小数再比较，所以"数学上相等"的两笔付款一定被判为同分，
由后两级规则决定先后，不会被浮点误差打乱。

## 四、与模块 3 的对接

模块 3 的 `m3engine/adapters.py` 会自动 `import module4_rank` 并调用
`rank_payments(queue, state, config)`。本文件夹根目录的 `module4_rank.py`
就是这个文件，**不需要改动模块 3 的任何代码**。

### 方式 A：把本文件夹加入 PYTHONPATH（推荐，不复制文件）

```powershell
$env:PYTHONPATH = "C:\Users\于沈豪\Desktop\第四模块"
python "C:\Users\于沈豪\Desktop\第三模块\module3\run_engine.py" `
  --dataset "C:\Users\于沈豪\Desktop\第三模块\module3\fixtures\pilot\low_rmb_liquidity\seed_1001" `
  --strategy S2 --out "C:\Users\于沈豪\Desktop\第四模块\outputs\manual"
```

然后检查 `run_summary.json` 里的 `using_fallback_module4` 必须是 `false`。

### 方式 B：复制进模块 3

把 `module4_rank.py` **和整个 `m4rank` 文件夹**一起复制到
`第三模块\module3\m3engine\` 下，然后设置：

```powershell
$env:M3_MODULE4_MODULE = "m3engine.module4_rank"
```

### 方式 C：一条命令完成 A 并自动检验

```powershell
python run_module4.py integrate --module3 "C:\Users\于沈豪\Desktop\第三模块\module3"
```

`integrate` 会自动找到模块 3（也支持 `--module3` 手动指定）、设置环境变量、
跑完 S0—S4、写出三张结果表，并断言 S2／S4 没有使用 fallback。

## 七、已知限制（写报告时要说明）

1. **S3／S4 还有一半是 fallback**。模块 5（等待／换汇决策）尚未交付，所以
   S4 目前只是"S2 + 立即换汇"。**S3／S4 的数字不能写进报告**，只有 S2 是真实的。
2. `w_L`（大额付款降权）初始为 0，与提案"初始实验关闭该因子、单独检验"一致。
   `L` 分项照样计算并记录，但不影响默认排序。
3. 默认权重下 `w_A·A` 最大只有 0.15，小于 URGENT 与 NORMAL 之间 `w_P·P` 的 0.30
   差距，所以老化**不可能**让普通付款超过紧急付款。这是有意设计：默认权重下老化
   只解决"同优先级内部谁先走"，要跨优先级生效必须提高 `weight_aging`（见 `sweep`）。
4. 排序函数没有记忆，不知道"这笔已经被跳过几次"，因此不模拟惩罚性老化。
5. NORMAL 的 P95 变差是真实发现，不是 bug：把有限的人民币集中给紧急款和临期款，
   普通款的尾部就会被推后。这正是提案要求"同时报告完成率和延迟"的原因。
